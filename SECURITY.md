# Security Policy

GhostRedRecon is offensive-security tooling for authorized red-team and owned-lab assessment only.

## Supported Scope

Security reports should focus on defects in the project itself, including unsafe defaults, accidental data exposure, command injection, path traversal, sensitive artifact leakage, or unsafe execution behavior.

## Reporting

Open a private security advisory or contact the project maintainer before public disclosure. Include:

- Affected version or commit.
- Reproduction steps.
- Impact and affected component.
- Suggested mitigation if known.

## Sensitive Data

Do not include real PCAPs, camera media, credentials, private MAC/IP inventories, or third-party network identifiers in public issues. Sanitize evidence before sharing.

## Authorized Use

Only run GhostRedRecon against systems and networks where you have explicit permission. The maintainers do not authorize misuse against third-party infrastructure.
